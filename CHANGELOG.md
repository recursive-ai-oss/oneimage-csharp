# Changelog

All notable changes are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- `RecursiveAI.OneImage.Text`, a separate package for fonts and text: `FontCollection` loads TrueType, OpenType/CFF, TrueType Collections and WOFF 1.0 (own inflate); `TextOptions` (origin, wrapping, line spacing, tab width, dpi, horizontal, vertical and text alignment, kerning), `TextMeasurer` (advance, ink bounds, lines, character boxes), `TextBuilder.GeneratePath` (text as a `Path`) and `DrawText` on `Image` and `Canvas` with a brush and/or pen. Outlines, advances, kerning, line counts and bounds match SixLabors.Fonts 2.1.3; rendering agrees with ImageSharp.Drawing 2.1.7 DrawText to coverage differences. See `docs/text.md`. A fuzz target `font` covers the parsers.
- OpenType shaping in `RecursiveAI.OneImage.Text`: GDEF glyph classes and mark filtering sets, GSUB lookup types 1-8 and GPOS types 1-9 with all lookup flags, so ligatures (`fi`, `ffl`), `ccmp` compositions, language forms (`locl`), contextual alternates, pair kerning and mark positioning on bases, ligatures and other marks work for Latin, Greek and Cyrillic. `TextOptions.Features` (`FontFeature.On("smcp")`, `Off("liga")`, alternates by value) and `TextOptions.Language` choose features and language forms; `KerningMode.None` is the `kern` feature off. Lookups are bounded in depth, work and growth, and damaged layout tables are ignored. Glyph ids and origins match SixLabors.Fonts 2.1.3 on Noto Sans; measuring and drawing a ligature-heavy paragraph is 8x and 19x faster. See `docs/text.md`.
- Unicode text segmentation in `RecursiveAI.OneImage.Text`: wrapping now ends lines at the break opportunities of the Unicode line breaking algorithm (UAX #14, Unicode 17.0: spaces, hyphens, soft hyphen, zero width space, no-break space and word joiner, quotation marks and brackets, numbers, East Asian text, Korean syllables, emoji sequences, flags), and never inside an extended grapheme cluster (UAX #29): `GetCharacterBounds` returns one box per cluster. New `TextOptions.WordBreaking` (`Standard`, `BreakAll`, `KeepAll`, `BreakWord`) and `TextOptions.TextJustification` (`None`, `InterWord`, `InterCharacter`), with ImageSharp's names and behavior. The property tables (72 KB) are generated from the Unicode Character Database by `tools/gen_unicode_tables.py`; `LineBreakTest.txt` (19,338 cases) and `GraphemeBreakTest.txt` (766 cases) pass in full. Ordinary text wraps at the same places as SixLabors.Fonts 2.1.3 (1,590 cases, none different), and justification matches it to 0.0001 px; text with break opportunities inside words differs, and `docs/text.md` lists why.

### Changed

- `Canvas.Fill(..., linear: true)` (and `Draw` with `linear: true`) no longer reads the canvas through a public snapshot: without an outside snapshot it swaps in fresh pooled tiles and returns the replaced ones, and it gives back the tiles its one-shot graph cached, which used to fill the shared tile cache (up to its 256 MiB budget) until the canvas was collected. A linear-light fill of a circle on a 2000 x 2000 canvas allocates 65 MB instead of 82 MB, with identical output. The color for a linear-light solid fill is now computed without leaving a pooled tile behind.
- `Canvas.Clip` no longer copies tiles through a public snapshot: it swaps in fresh pooled tiles and returns the replaced and cached ones to the pool. A blur clipped to a circle on a 2000 x 2000 canvas allocates 88 KB instead of 9.6 MB, at the same speed and with identical output.

- WOFF 2.0 fonts in `RecursiveAI.OneImage.Text`: `FontCollection.Add` and `AddCollection` read single fonts and collections, with the transformed `glyf`/`loca` and `hmtx` tables, on the package's own Brotli decoder (RFC 7932, safe managed code; the BCL decoder is native and is not used). Declared sizes and expansion are bounded before anything is allocated. Faces, outlines, advances, kerning and shaping equal the source fonts'. A fuzz target `brotli` joins `font`. See `docs/text.md`.
- Color glyphs in `RecursiveAI.OneImage.Text`: `TextOptions.ColorFontSupport` (`MicrosoftColrFormat` by default, as in SixLabors.Fonts; `None` turns it off) and `ColorPaletteIndex` make `DrawText` on `Image` and `Canvas` paint COLR version 0 layers with CPAL palette colors or the brush (palette index 0xFFFF); `Font.ColorPaletteCount` and `Font.HasColorGlyph`. Matches ImageSharp.Drawing 2.1.7 to a mean of 0.07 levels on a layered test font. COLR version 1 glyphs draw as their plain outline. Text as a path stays monochrome.

## [1.1.0] - 2026-10-22

### Added

- Vector drawing foundation (`OneImage.Drawing`): `Path`, `PathBuilder` (lines, quadratic and cubic Béziers, SVG elliptical arcs), shape factories (rectangle, rounded rectangle, ellipse, circle, polygon, regular polygon, star, combine), transforms, reverse, length, bounds, flattening, and strict bounded SVG path-data parsing (`Path.TryParseSvg`). `Image.Fill`, `Image.Clear`, `Canvas.Fill` and `Canvas.Clear` fill paths with a solid `Brush`: exact-area anti-aliasing (or none), non-zero and even-odd rules, blend modes, Porter-Duff operators, opacity, a transform, and linear-light blending. `Image` fills are lazy and a run of fills computes in one pass; `Canvas` fills draw in place in parallel with identical bytes. See `docs/drawing.md`. A fuzz target `svg` covers the path parser.
- Strokes: `Image.Draw` / `Canvas.Draw` with a `Pen` (any brush, width, `StrokeJoin` Miter/Round/Bevel/Square with a miter limit, `StrokeCap` Butt/Round/Square, dash patterns with offset, presets Dash/Dot/DashDot/DashDotDot) or a color and width; helpers `DrawLine`, `DrawPolyline`, `DrawPolygon`, `DrawBeziers`, `DrawRectangle`, `DrawEllipse`; and `Path.GenerateOutline` returning the stroke as a `Path`. Overlapping parts of one stroke are painted once, so translucent pens are even. 6 to 7 times faster than ImageSharp.Drawing on strokes with a fifth to a quarter of the allocation; see `docs/drawing.md`.
- Brushes for fills (`OneImage.Drawing.Brush`): linear, radial and elliptic gradients with color stops and the repetition modes none, repeat, reflect and dont-fill; a path gradient; pattern brushes with the hatch presets (horizontal, vertical, forward and backward diagonal, 10%, 20%, min); an image brush with region, offset, transform and tiling; and a recolor brush. Gradients interpolate premultiplied colors in encoded values by default and blend in linear light with `linear: true`, which now works with every brush. `Brush` is public to derive from: implement `FillRow` (and `ReadsBackdrop` for brushes that read the existing pixels). Opaque brush colors over fully covered pixels are written directly, through a vector kernel for 8-bit RGBA. Agrees with ImageSharp.Drawing 2.1.7 to rounding on every brush and mode; see `docs/drawing.md` for the differences.
- `Image.Composite(..., blend:, alpha:)`: all 24 Photoshop/W3C blend modes (`BlendMode`: Multiply, Screen, Overlay, Darken, Lighten, Color Dodge/Burn, Hard/Soft/Vivid/Linear/Pin Light, Hard Mix, Difference, Exclusion, Add, Subtract, Linear Burn, Divide, Hue, Saturation, Color, Luminosity) and the twelve Porter-Duff operators (`AlphaComposition`). Normal source-over output is unchanged.
- `Image.Perspective`: a projective (perspective) transform from a `ProjectiveMatrix`, a `ProjectiveTransformBuilder` (taper, rotation, scale, skew, translation, matrices, with `Append` and `Prepend` forms) or four corner points. `ProjectiveMatrix` also builds quad-to-quad maps.
- `Fit.BoxPad` and `Fit.Min` (ImageSharp's `ResizeMode.BoxPad` and `Min`), the aliases `Fit.Max` and `Fit.Crop`, and `Image.ResizeInto` for resizing into a rectangle of a canvas (`ResizeMode.Manual`).
- Resampling filters `Hermite`, `Lanczos5`, `Lanczos8`, `Robidoux`, `RobidouxSharp`, `Spline` and `Welch`, with the aliases `Bicubic` and `Triangle`, in `Resize` and in the rotate, affine and perspective samplers.
- Neighbourhood effects, matching ImageSharp 3.1.12: `Pixelate`, `OilPaint`, `Vignette`, `Glow`, `BokehBlur`, `GaussianSharpen`, `DetectEdges` (`EdgeDetector`: Sobel, Prewitt, Scharr, RobertsCross, Kayyali, Laplacian3x3/5x5, LaplacianOfGaussian, Kirsch, Robinson) and `EntropyCrop`. `OilPaint` centers its window, where ImageSharp's is shifted; see the migration guide.
- Color matrix: `Image.ApplyColorMatrix(ColorMatrix)` with a public `ColorMatrix` (ImageSharp's 5x4 layout), and the looks built on it: `Sepia`, `BlackWhite`, `Kodachrome`, `Lomograph`, `Polaroid`, `ColorBlindness(ColorBlindnessMode)` and `Opacity`. `Lomograph` and `Polaroid` include ImageSharp's vignette and glow; `ColorMatrix.Lomograph` and `.Polaroid` are the plain matrices. They fuse with the other color ops into one pass per tile, and a color chain directly on a decode now runs on rows as they are decoded when the whole frame is read at once.
- `Image.HistogramEqualization`: global, adaptive tile interpolation and adaptive sliding window equalization with histogram clipping, luminance levels and tile count, matching ImageSharp 3.1.12 within 1 level at 8 bits (`HistogramEqualizationMethod`). The luminance is mapped and written to all color channels, as in ImageSharp.
- `RecursiveAI.OneImage.Web`, a separate package with ASP.NET Core middleware for on-the-fly image processing (`AddOneImage()` / `UseOneImage()`): URL commands for size, fit, anchor and focal point, filter, background, format, quality and orientation, with ImageSharp.Web query names accepted too; presets and a presets-only mode; web root, folder, `IFileProvider` and custom providers; a disk cache with configurable layout, ETag and Last-Modified validators with 304 answers, source-change invalidation and single processing of concurrent identical requests; HMAC-signed URLs with a signer and a Razor tag helper; request hooks; and size, source and concurrency limits. See `docs/web.md`.
- Histograms, thresholds and dithering, matching ImageSharp 3.1.12: `Image.AutoLevel`, `Image.AdaptiveThreshold`, and a public `Image.Dither(palette, dither, scale, fastMatch)` (`fastMatch` defaults to true: ImageSharp's order-dependent cell matching, bit-identical to its output; `false` matches each pixel exactly) and `BinaryDither`. The `Dither` enum gains Atkinson, Burkes, JarvisJudiceNinke, Sierra2, Sierra3, SierraLite, StevensonArce, Stucki, Bayer2x2, Ordered3x3, Bayer4x4, Bayer8x8 and Bayer16x16 (they also work in `Quantize` and the GIF encoder). `Quantizer` (Wu, Octree, WebSafe, Werner) selects the palette builder in `Quantize` and `GifEncoderOptions.Quantizer`, and `KnownPalettes.WebSafe` and `KnownPalettes.Werner` are public. Existing GIF and indexed-PNG output is unchanged.
- Boolean operations on paths: `PathBoolean` (`path.Boolean(BooleanOperation, other, ...)`, `Union`, `Intersect`, `Subtract`, `Xor`, `UnionAll`, `Resolve`, `Offset`) with exact integer geometry on a 1/256 px grid, per-operand non-zero or even-odd rules, and polygon results without overlaps. `Image.Clip(path, operations)` / `Canvas.Clip` run any operations only inside a path with anti-aliased edges, and `Fill` / `Draw` take `clip:` to limit a shape to a clip path. A 200-circle union takes 7 ms against ImageSharp.Drawing's 11 ms with one seventh of the allocation, and a Gaussian blur clipped to a circle on 2000 x 2000 takes 12-13 ms against 56 ms; see `docs/drawing.md`.

## [1.0.0] - 2026-10-22

First release, published on NuGet as `RecursiveAI.OneImage` (namespace `OneImage`).

### Added

- Lazy, immutable `Image` and mutable tiled `Canvas` on one engine, with O(1) snapshots.
- Codecs: PNG (including APNG and indexed output), JPEG (baseline, progressive, arithmetic, 12-bit, CMYK, shrink-on-load), WebP (lossy, lossless, animation), GIF (animation, quantizing, dithering), TIFF (including BigTIFF, CCITT and multi-page), BMP and ICO.
- ICC color management (v2 and v4 profiles, built-in profiles, a generic CMYK profile), resampling in linear light, geometry, tone and filter operations, analysis, and normal-mode compositing.
- `Image.Thumbnail`, which applies EXIF orientation, converts to sRGB and strips EXIF, XMP and IPTC by default.
- Size limits on by default, checked from headers before allocation; typed exceptions; a fuzz target for every decoder and parser.
- Depends only on the .NET base class library; NativeAOT- and trim-compatible.
- Documentation: a guide, a migration guide from ImageSharp and System.Drawing, a comparison with other libraries, and a [performance page](https://github.com/recursive-ai-oss/oneimage-csharp/blob/v1.0.0/docs/performance.md) with the benchmark method and every loss.
